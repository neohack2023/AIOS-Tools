# Cartography Slice 8 — Governed System-Graph Coverage Expansion

## Purpose

Expand the Slice 7 proof fixture into a bounded, source-backed AIOS system graph without changing the Workbench shell, layout strategies, or GPU renderer.

## Authority boundary

- Notion remains architectural and governance authority.
- Google Drive remains drive_shadow, registry, and execution-evidence storage.
- GitHub remains executable implementation truth.
- A graph object is included only when it has an exact source-system identifier and source pointer.
- Similar titles, fuzzy matching, inferred mirrors, and decorative subsystem nodes are prohibited.
- Unresolved coverage is recorded as a coverage gap, not rendered as a knowledge node.

## Included domains

1. Governance
2. Registries
3. Project branches
4. Retrieval and context assembly
5. Workflows and routing
6. STONE and MASON
7. Observability and runtime telemetry
8. GitHub implementation state

## Included implementation

- Expand `SOURCE_BACKED_FIXTURE` from the Slice 7 shell proof into a cross-source system snapshot.
- Add exact Notion objects for governance, registries, project branches, retrieval, workflows, STONE/MASON, telemetry, and Cartography.
- Add exact Drive objects for the root hierarchy, registry sheets, runtime registries, and selected drive_shadow contracts.
- Add exact GitHub repository and implementation-path nodes for the Cartography application, Python core, Graph IR schema, and CI gate.
- Add cross-source relationships for exact registered mirrors, runtime backing, and implementation.
- Add a typed coverage report with resolved domains and explicit unresolved items.
- Add the `IMPLEMENTATION` authority filter to the Workbench.
- Show coverage counts in the Navigator without changing renderer behavior.
- Add deterministic source-coverage unit tests.
- Update browser assertions for the expanded graph while preserving existing interaction and screenshot gates.

## Explicit exclusions

- No source writes from the browser.
- No live connector credentials in the browser.
- No automatic identity reconciliation.
- No fuzzy object discovery.
- No runtime execution-instance ingestion.
- No row-level expansion of entire registry spreadsheets.
- No renderer or layout rewrite.
- No hosted deployment claim.
- No Active promotion.

## Acceptance gates

1. The snapshot contains all eight declared coverage domains.
2. Every rendered node has a non-empty exact source object ID and source pointer.
3. Notion, Google Drive, and GitHub are each represented as distinct source systems.
4. GitHub implementation nodes use authority role `IMPLEMENTATION`.
5. Cross-source mirror and implementation edges resolve to existing node IDs.
6. The graph contains no placeholder or synthetic subsystem node.
7. Unresolved coverage appears only in the typed coverage report.
8. Mind Map, Lineage, Outline, search, URL state, and GPU fallback behavior remain operational.
9. TypeScript build, unit tests, Playwright interactions, screenshot regressions, Python checks, and Repository Governance pass.
