# AIOS-Tools Review Rules

State: `PHASE_3_ACTIVE / PROMOTION_GOVERNED`

This is the compact review router for `review-pr`. It does not duplicate the repository's canonical authority, architecture, development, validation, contract, policy, or department instructions.

## Common review law

1. Resolve exact candidate/head identity before trusting evidence.
2. Load the most specific touched-area `.github/instructions/*.instructions.md` packet.
3. Check the candidate against `docs/AUTHORITY_BOUNDARIES.md`, relevant contracts/policies/fixtures/tests/workflows, and its governing plan/contract.
4. Treat review as advisory and verifier PASS as obligation-local.
5. Reject silent capability, credential, network, durable-write, release, deploy, or authority widening.
6. Require fail-closed behavior where repository law or contracts require it.
7. Do not claim checks passed unless execution evidence exists for the identity being claimed.
8. A candidate-head change stales head-bound review/verification evidence unless transferability is explicitly proven.

## Learning loop

`review finding -> harvest-lesson -> candidate -> human/governance adjudication -> promoted rule/test/verifier obligation OR rejection`

`docs/agent-system/lessons/CANDIDATES.md` contains candidate memory. Candidates are not enforceable review law merely because they exist.

## Promotion targets

When explicitly authorized, a lesson should be promoted into the smallest appropriate existing surface:
- common repository law: `AGENTS.md` or this review router;
- department-specific law: matching `.github/instructions/*.instructions.md`;
- executable acceptance: tests/workflows/contracts/policies;
- explanatory context: existing canonical docs.

Do not create duplicate law merely to preserve a lesson.
